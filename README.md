# 红色房间 · WebXR

以 1990–1991 原剧为依据，将现有 Blender v7 场景转换成可自由探索的 WebXR 体验。全局连接、完整尺寸和循环变化属于推定与创作。

## 本地启动

Windows 双击 `start-local.cmd`：后台启动本地服务并在浏览器打开 **http://localhost:4173**。再次双击会复用本项目的服务、重新打开网页。关闭浏览器不会停止服务；需要结束时双击 `stop-local.cmd`。开机后重新双击启动即可。

试窗帘交互可直接打开 **http://localhost:4173/?curtains**，进入等候室左侧的红帘旁。按 W 轻靠帘幕，S 退开观察回弹，A / D 沿帘横移；“回到起点”回到经典全景位置。

右上角“画面”提供原始、胶片、梦境三档，默认胶片、强度 65%。胶片加入柔光、暖色光晕、细颗粒和轻微暗角；梦境提高朦胧感。用滑杆调整强度，按 V 在原始与上次选择的效果间对比。偏好仅保存在当前浏览器；`?look=film` / `?look=dream` / `?look=clean` 可直接指定风格，并可与 `?curtains` 组合。

只需已安装 [Node.js LTS](https://nodejs.org/)。模型、Three.js 与解码器已随项目提供，**运行不需要 `npm install`，也不需要在线站点或账号**。完整保留 `dist` 文件夹；直接双击 HTML 无法加载浏览器模块与模型。

也可以从任何目录用命令启动前台服务（关闭终端或按 Ctrl+C 停止）：

```sh
node /path/to/red-room-xr/server.mjs
```

端口被其他程序占用时，启动器会给出提示，不会结束该程序。PowerShell 可执行 `./start-local.ps1 -Port 4174`，停止时使用 `./stop-local.ps1 -Port 4174`；前台命令支持 `node server.mjs --port 4174` 或环境变量 `PORT`。运行日志位于 `.local/`。

## 漫游与头显

进入：点击“进入房间”后画面先沉入黑场，房间底噪先响起，约 1.5 秒后房间缓缓显现。同一次点击会锁定鼠标用于环顾。

电脑：WASD / 方向键行走，起步与停步有短暂的加减速。移动鼠标环顾；Esc 先释放鼠标，再按一次回到菜单；单击画面（或按 M）重新锁定，也可以按住拖动转头。手机：方向按钮移动，拖动画面转头。

漫游时画面上只有房间：操作提示与按钮在进入后停留几秒再隐藏，移动鼠标或释放鼠标锁定时重新出现，触屏设备始终保留。“路线微光”与“步行起伏”在“?”说明面板中开关，路线也可按 G 切换，两者默认关闭；路线微光沿通道连续显示，跟随拐角前行。完整绕行后，米洛雕像消失，镜像房换成双人椅与紫帘，再走一圈恢复。变化不以文字提示，只有房间底噪会短暂中断。重置回到第一圈。

VR：在支持 WebXR 的浏览器与设备环境中，选择“进入 VR”。按住手柄扳机瞄准，松开传送；摇杆左右拨动，每次转向 30°。A / X 切换路线提示，双手握键同时按住 1.2 秒回到起点，提前松开取消。视野内会显示简短提示与重置进度。头部视角由头显跟踪，使用头显系统菜单结束会话。电脑浏览器通过兼容的 PC VR 运行环境连接头显时，可使用本机 localhost；能否进入由浏览器的 `immersive-vr` 支持检测决定。

`localhost` 指正在浏览网页的那台设备。本地 HTTP localhost 属于浏览器可信任来源；普通局域网 HTTP 地址不能等同于 localhost。[浏览器安全上下文说明](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts#potentially_trustworthy_origins)、[WebXR 权限说明](https://developer.mozilla.org/en-US/docs/Web/API/WebXR_Device_API/Permissions_and_security)。

独立头显访问电脑服务时，可以在设备支持 USB 调试的前提下配置开发端口转发：电脑 Chrome 打开 `chrome://inspect/#devices`，启用 USB 设备发现与端口转发，将设备端口 `4173` 映射至电脑 `localhost:4173`，再在设备浏览器打开 `http://localhost:4173`。这依赖设备的开发模式、USB 授权和浏览器兼容性；尚未用实体头显验证。[Chrome 官方端口转发步骤](https://developer.chrome.com/docs/devtools/remote-debugging/local-server#port-forwarding)。本服务默认仅监听电脑回环地址，不开放局域网访问。

## 声音

全部声音由 Web Audio 实时合成，没有音频文件：两路微失谐的低频嗡鸣、低沉的房间底噪和极轻的电流声缓慢起伏；脚步按实际行走距离落在地面上，VR 传送落点也有一步；贴近或触碰红帘会发出布料摩擦声，左右声像跟随接触位置。脚步与布料经过一个很短、高频先衰减的房间响应，模拟丝绒吸音的近场。

声音随“进入房间”或“进入 VR”的点击开始，回到菜单时降低，切到后台标签页时暂停。右上角“声音”按钮可静音，偏好只保存在当前浏览器。`?debug` 下 `__redRoom.audio.inspect()` 给出播放状态与触发计数。

## 实现与验证

静态 HTML / CSS / ES modules；Three.js 0.186.1 自托管，运行时没有第三方 CDN、控制器模型下载、用户数据收集或后端依赖。1 单位 = 1 米；Y 轴向上。`simulation.js` 独立管理地面范围、碰撞、按顺序到访的路线检查点和房态。`xr-controls.js` 管理双手柄弧线、传送和绕真实头部位置的分段转向。

GLB 由原生 Blender v7 减面导出。灯光以 Cycles 采样烘焙到顶点颜色，避免头显实时计算大量灯光。本地优化版调整了初始构图，补充暖色地板微光、家具边缘反光与远处暗化。原生 Blender 文件保持不变。实时版本与离线最终渲染存在细节差异。

运行时校色以 1991 原片经典机位为参照（`../改进规划/色彩对照.py` 可重复测量）。红帘在材质中压掉烘焙残留的绿、蓝分量，并略增中间调对比，回到原片的纯红；紫色梦境帘保持原色。地板按条纹区分浅、深两色，染上帘幕反射的暖粉与深红，离帘越近越红、越暗：载入时由帘幕碰撞线生成 0.2 m 精度的距离场贴图，帘脚约 0.9 m 内逐渐压暗，同时遮住地板裁切留下的锯齿边。第二圈 F 房换成紫帘时，地板随之偏冷。胶片档不再降低饱和度，暗部改为暖色抬升。

红帘会响应近距离擦过、靠住帘幕时的移动意图，以及 VR 中身体和已跟踪手柄的触碰。接触处产生小幅摆动，离开后余波逐渐衰减；帘顶、开口接缝和贴地边缘固定。每片帘幕独立响应，传送与跟踪跳变不会制造穿过整间房的冲击。这是局部形变效果，行走边界仍保持原场景通道。无人触碰时，帘幕也随约 9 秒和 5.6 秒两组慢波轻微起伏，下摆幅度约 1 cm；系统开启“减少动态效果”时停止。

`curtain-surfaces.js` 在载入时恢复每片帘的导线和固定边界；`curtain-motion.js` 生成最多 6 处衰减的接触信号；`curtains.js` 在原有帘幕材质中完成 GPU 形变与呼吸，不增加绘制批次。正常与梦境房共用对应帘幕的交互状态。`locomotion.js` 管理桌面与触屏行走的加减速、脚步节奏与可选的步行起伏；`audio.js` 生成程序化声音。

`film.js` 在桌面和手机中使用线性颜色的场景缓冲、两个低分辨率柔光 pass 和最后的调色合成，总共增加 3 个全屏绘制批次。支持时使用半浮点缓冲和最高 4× MSAA；最终仅转换一次显示色彩空间。原始模式和强度 0 直接渲染原画。VR 使用材质级轻量调色，保留原生双眼相机、清晰的空间边界和舒适渐黑，不套用屏幕模糊或双眼不一致的颗粒。减少动态效果偏好会冻结颗粒变化。

5 个 GLB 共约 3.11 MB，包含两个房态的帘幕布光。原始模型合计约 61 万三角形（含互斥状态）；按房间合并为 19 个资产绘制批次并进行视锥剔除。地板采用连续的近似照明和轻量接触阴影，避免分层地板烘焙自遮挡。使用 Meshopt 压缩；解码器一并自托管。以上为资产统计，不代表实体头显帧率。

```sh
npm ci # 仅开发与自动化测试需要安装依赖
npm test
npm run check
# 先保持 npm run preview 运行；QA 使用本机 Chrome
npm run qa
npm run qa:curtains
npm run qa:film
```

自动测试覆盖本地启动与停止、服务复用、端口冲突、HTTP 与缓存、门洞、墙体、家具、滑动碰撞、禁止穿墙传送、两圈状态恢复，以及模拟 XR 的头部偏移、转向枢轴、路线按钮和双握键重置。帘幕测试覆盖接触、擦过、静止衰减、相邻帘隔离、不同帧率、传送跳变和已跟踪手柄坐标。另通过桌面 Chromium WebGL、键盘/UI、手机布局与模拟触屏移动检查；帘幕浏览器检查会比较同机位的实际 GPU 像素变化，确认变形可见且不增加绘制批次。行走模块单元测试覆盖加减速、帧率无关、脚步节奏与异常输入。浏览器检查另覆盖入场黑场、声音触发计数、绕圈不弹文字、操作界面自动隐藏与鼠标唤出，以及无接触时帘幕的呼吸；声音只检查触发，不代表听感测试。实体头显性能、舒适性和不同设备的输入兼容性尚待实测。

后期验证覆盖固定机位、固定时间的三档像素对比，强度 0 与原始逐字节一致，画面面板、V 对比、强度滑杆、手机尺寸和窗帘动态兼容。模拟 XR 测试确认不分配或切换桌面后期缓冲，也不改变舒适遮罩与提示牌材质；这不等于实体头显测试。
